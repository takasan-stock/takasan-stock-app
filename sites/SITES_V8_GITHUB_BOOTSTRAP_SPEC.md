# Takasan Stock Hunter Sites v1 — Version 8 GitHub Bootstrap Fallback

## Goal

Prevent a completely blank first-run screen when:
- browser persistent cache is still empty, and
- Cloudflare/Render edge returns 429 before the Render application receives the request.

Use a read-only public market-data snapshot from GitHub as bootstrap data.

## Security boundary

The repository is public.

Therefore the GitHub bootstrap MUST contain public market-derived data only.

Allowed:
- summary
- EARLY

Forbidden:
- WATCHLIST membership
- WATCHLIST memo
- personal notes
- write state
- secrets
- API keys
- credentials
- chart browsing history

WATCHLIST continues to come only from the live Render API or the user's existing local cache.

## Snapshot URLs

Use:

```
https://raw.githubusercontent.com/takasan-stock/takasan-stock-app/sites-data/sites-bootstrap/meta.json
https://raw.githubusercontent.com/takasan-stock/takasan-stock-app/sites-data/sites-bootstrap/summary.json
https://raw.githubusercontent.com/takasan-stock/takasan-stock-app/sites-data/sites-bootstrap/early.json
```

The snapshot is generated by GitHub Actions after successful scanner runs and when the snapshot workflow changes.

## Startup priority

Use this priority:

1. Version 7 local persistent cache, if present.
2. If no local cache exists, load GitHub bootstrap summary/early immediately.
3. In parallel, run the existing Version 6 live health sequence.
4. If live Render data succeeds, live data replaces bootstrap/cache and is persisted locally.
5. If live data is blocked by 429, keep bootstrap/cache visible.

## GitHub bootstrap UI

When GitHub bootstrap is being shown, display:

```
初期スナップショットを表示中
取得日時: YYYY-MM-DD HH:mm
SOURCE: GitHub Snapshot
```

Do not label it as live/fresh Render data.

If snapshot age exceeds 24 hours, add:

```
データが古い可能性があります
```

## WATCHLIST behavior

GitHub bootstrap contains no WATCHLIST.

If local WATCHLIST cache exists:
- use that cache while live API is unavailable.

If no local WATCHLIST cache exists:
- show WATCHLIST KPI as "—", not 0.
- show a neutral note:
  `WATCHLISTはLive API接続後に取得します`
- do not fabricate a zero count.
- TODAY ACTION QUEUE may use EARLY candidates only.
- do not show "登録済み" unless confirmed by local cache or live API.

## Ranking / TODAY / EARLY

GitHub summary and early may populate:
- 総合候補
- EARLY TOP20
- 理想本命
- RANKING
- 今日見るべきEARLY
- EARLY由来のTODAY ACTION QUEUE候補

ENTRY確認 is WATCHLIST-derived:
- if watch cache unavailable, display "—".

## Chart

Do not publish charts in GitHub bootstrap.

Chart fallback order remains:
1. live API
2. Version 7 local chart cache
3. no chart available

If neither live nor cache is available, show a clear neutral message.

## Fetch policy

GitHub bootstrap fetch is GET-only.

- no aggressive retry
- one fetch batch per startup when local cache is absent
- no background polling
- validate HTTP 200 and JSON shape before use
- failure must not erase existing local cache

## Validation

Validate:
- meta.schema_version == 1
- summary.rows is an array
- early.rows is an array
- meta.watchlist_included == false

If validation fails, ignore bootstrap and continue existing behavior.

## Source precedence

Never let an older GitHub bootstrap overwrite:
- fresher live data
- fresher local cache

Compare timestamps when available.

## Version 6 / 7 behavior remains

Keep:
- single-flight
- 429 circuit breaker
- 60-second cooldown
- 502/503/504 retry
- relay/direct behavior
- local persistent cache
- write safety
- J-Quants primary source

Version 8 only adds a safe initial read fallback.

## Save / deploy

Save as Version 8.
Deploy with current private / 本人限定 access.
Do not modify Render configuration.
